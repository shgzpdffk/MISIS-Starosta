# Размещение на Amvera

Приложение запускается одним Docker-контейнером: HTTP API, Telegram long polling и обработчик очереди. Отдельная БД или npm-установка на этапе сборки не нужны. Python-зависимости устанавливает Dockerfile.

## Новый проект

1. Создайте приложение Amvera с Docker-сборкой. Загрузите **содержимое корня репозитория** в Code или подключите репозиторий доступным в панели способом. `Dockerfile` и `amvera.yml` должны лежать в корне, без дополнительной обёртки-папки.
2. Получите HTTPS-домен приложения и добавьте переменные:

| Переменная      | Значение                                                      |
| --------------- | ------------------------------------------------------------- |
| `BOT_TOKEN`     | Токен вашего бота, секретная переменная                       |
| `APP_URL`       | Публичный HTTPS-адрес приложения                              |
| `BOT_ENABLED`   | `true`                                                        |
| `DATABASE_PATH` | `/data/misis/misis.sqlite` — значение Dockerfile по умолчанию |

`HOST=0.0.0.0`, `PORT=3000` и `PYTHON_BIN` уже настроены в образе. `MISIS_CATALOG_PATH` необязателен: по умолчанию каталог находится рядом с базой. Не подменяйте эти пути локальными путями с компьютера.

3. Выполните сборку. В конфигурации проекта используются порт `3000` и постоянное хранилище `/data`. Это соответствует [Docker-конфигурации Amvera](https://docs.amvera.ru/applications/configuration/docker.html).
4. Откройте адрес приложения с `/health`. Для версии 0.3.0 ожидается `ok: true`, `version: "0.3.0"`. `botConfigured: true` означает наличие токена, но не подтверждает успешное соединение с Telegram.
5. Проверьте журнал запуска и отправьте боту `/start`. Откройте кнопку «Моя группа». В BotFather можно дополнительно настроить Main Mini App на тот же HTTPS-адрес.
6. Заполните профиль, создайте группу и загрузите каталог МИСИС через экран расписания. Проверьте предпросмотр, недели и подгруппы перед импортом.

## Обновление существующего приложения

1. Сделайте резервную копию SQLite согласно [инструкции эксплуатации](docs/OPERATIONS.md). Сохраните предыдущую версию исходников для отката.
2. Обновите файлы **Code** или ревизию подключённого репозитория. Для этой подготовки к open source версия функций остаётся 0.3.0, новых переменных окружения не требуется.
3. Сохраните существующие `BOT_TOKEN`, `APP_URL`, `BOT_ENABLED` и путь базы. **Не очищайте Data**. Постоянные данные хранятся в Data и монтируются при запуске, а Code заменяется при пересборке: [хранилище Amvera](https://docs.amvera.ru/applications/storage.html).
4. Пересоберите и перезапустите приложение. Закройте Mini App полностью и откройте снова.
5. Проверьте `/health`, `/start`, существующую группу, профиль и расписание. Для этой подготовки отличием чистой установки будет первая загрузка каталога; существующий каталог в Data продолжит использоваться.

При переходе с 0.1/0.2 приложение перед добавлением таблиц создаёт `.pre-v0.2.0-backup` / `.pre-v0.3.0-backup` рядом с базой. Эти копии не заменяют регулярные резервные копии оператора. При ошибке создания копии запуск останавливается.

## Если что-то не работает

- Нет доступа к базе: проверьте постоянный каталог и права записи; entrypoint подготавливает пути и запускает Node от непривилегированного пользователя.
- Демо вместо своей группы: открывайте через кнопку бота, а не обычную вкладку браузера.
- Ошибка авторизации: откройте Mini App заново, проверьте соответствие токена боту.
- Нет уведомлений: пользователь должен нажать `/start`; проверьте тихие часы, личные настройки и отметку «Буду на всех парах».
- Telegram сообщает конфликт: должен работать один экземпляр long polling. Проверьте, что тот же бот не запущен на компьютере или другом сервере и у него нет активного webhook.
- Пустой каталог: нажмите первую загрузку на экране расписания. Ошибки сети МИСИС и неподдерживаемые файлы требуют повторной попытки или ручного ввода.

Docker Compose и Caddy для Amvera не используются: HTTPS обслуживает платформа. Они нужны только для отдельного VPS.
