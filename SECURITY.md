# Безопасность

Проект находится в beta. Исправления безопасности принимаются для текущей версии в основной ветке; отдельные сроки поддержки старых версий не заявлены.

## Сообщить об уязвимости

Не публикуйте токены, initData Telegram, базы, имена студентов или рабочие ссылки приглашений в открытом Issue.

Если в GitHub-репозитории включена функция **Security → Report a vulnerability**, используйте её для приватного сообщения. Если такой кнопки нет и приватный контакт владельца не указан, создайте Issue с просьбой предоставить приватный канал, без описания способа эксплуатации и реальных данных. Не используйте публичные Issues для передачи секретов.

Для воспроизведения достаточно версии, описания нарушенной границы доступа, минимального примера на вымышленных данных и ожидаемого результата.

## Границы проекта

- Сервер проверяет HMAC Telegram initData, срок действия, Origin при наличии и членство пользователя в группе.
- Браузерное демо не авторизует пользователя в серверных API.
- Права на вложения проверяются отдельно; файлы хранятся в SQLite. Антивирусная проверка вложений не реализована.
- Владелец сервера имеет доступ к базе, в том числе к обращениям и вложениям. Шифрование базы на диске приложение самостоятельно не обеспечивает.
- HTTPS, резервные копии, доступ к переменным окружения и диску — ответственность оператора размещения.
- Удаление/выход из группы и срок хранения данных имеют разные последствия: выход студента сохраняет исторические отметки. Политика хранения и удаления данных должна быть определена оператором.

Автоматические тесты и линтеры не являются независимым аудитом безопасности.
