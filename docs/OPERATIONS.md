# Эксплуатация

## Настройки

| Переменная           | По умолчанию вне Docker         | Назначение                                               |
| -------------------- | ------------------------------- | -------------------------------------------------------- |
| `HOST`               | `127.0.0.1`                     | Адрес прослушивания                                      |
| `PORT`               | `3000`                          | Порт HTTP                                                |
| `BOT_TOKEN`          | пусто                           | Секрет BotFather                                         |
| `APP_URL`            | пусто                           | Единый HTTPS-адрес интерфейса и API                      |
| `BOT_ENABLED`        | `false`                         | Запуск long polling и очереди, включается строкой `true` |
| `DATABASE_PATH`      | `./data/misis.sqlite`           | SQLite и вложения                                        |
| `MISIS_CATALOG_PATH` | `misis-data.json` рядом с базой | Постоянный каталог МИСИС                                 |
| `PYTHON_BIN`         | `python3`                       | Python с установленными xlrd и openpyxl                  |
| `APP_DOMAIN`         | нет                             | Только Compose/Caddy: домен без схемы                    |

Не используйте одновременно несколько экземпляров приложения с одной базой или одним токеном. Фоновая доставка и публикация объявлений запускаются вместе с ботом. Если `BOT_ENABLED=false`, работает HTTP/демо, но не фоновая отправка.

## Docker Compose на VPS

Установите Docker с Compose, направьте DNS домена на сервер и обеспечьте доступ к портам 80/443. Скопируйте `.env.example` в `.env`, заполните токен, `APP_DOMAIN`, `APP_URL=https://ваш-домен` и `BOT_ENABLED=true`.

```sh
docker compose up -d --build
docker compose logs --tail=100 app
```

Caddy получает сертификат и проксирует запросы в приложение. Данные находятся в volume `app-data`, база внутри app-контейнера — `/app/data/misis.sqlite`. Пересборка сохраняет volume; команда `docker compose down -v` удаляет его, поэтому для обычного обновления она не подходит.

В отдельном Dockerfile значение пути — `/data/misis/misis.sqlite`; Compose намеренно переопределяет его для своего volume. На Amvera используйте [AMVERA.md](../AMVERA.md).

## Копирование и восстановление

Для работающей SQLite в WAL-режиме используйте SQLite backup API или `VACUUM INTO` в новый файл. Простое копирование только `.sqlite` во время записи может потерять изменения из WAL.

Вариант без специальных инструментов:

1. Остановите приложение и дождитесь завершения процесса.
2. Скопируйте постоянный каталог целиком, включая базу, каталог расписаний и оставшиеся `-wal`/`-shm`, если они есть. Храните копию с закрытым доступом.
3. Запустите приложение и проверьте группу.

Для восстановления остановите приложение, сохраните текущую папку отдельно и восстановите согласованную копию. Не смешивайте базу и WAL из разных копий. Версия кода должна поддерживать схему восстановленной базы. Проверяйте восстановление периодически, а не только существование файла копии.

## Просмотр сообщений об ошибках

Утилита работает непосредственно на сервере с доступом к SQLite и открывает её только для чтения:

```sh
node --env-file-if-exists=.env scripts/requests.mjs
node --env-file-if-exists=.env scripts/requests.mjs --id REQUEST_ID
node --env-file-if-exists=.env scripts/requests.mjs --id REQUEST_ID --file ./attachment.bin
```

Она показывает последние 100 сообщений об ошибках или одно обращение с автором и временем. `REQUEST_ID` замените реальным ID из списка. Вложение сохраняется в новый файл без перезаписи существующего. Его содержимое и список обращений являются пользовательскими данными: не добавляйте их в Git.

В Compose команду можно выполнить через `docker compose exec app node scripts/requests.mjs`. Для Amvera используйте доступ к терминалу приложения, если он предусмотрен вашим способом работы с платформой. Переменная `DATABASE_PATH` должна указывать на рабочую базу, а не на временную копию.

## Контроль работы

`GET /health` проверяет доступность HTTP-процесса и показывает версию. Он не гарантирует связь с Telegram, актуальность расписания или доставку очереди. Дополнительно проверяйте журналы, свободный диск, возможность открыть существующую группу и тестовый опрос.

Обращения и их вложения находятся в отдельной таблице; лимит JSON группы не является общим лимитом диска. Встроенная автоматическая очистка старых обращений отсутствует. Оператор определяет сроки хранения и порядок удаления данных.
